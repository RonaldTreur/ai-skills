# Pruning campaign

A campaign prunes one subsystem's whole test surface (a package, a public entry point, a plugin, one core area) in one long-lived PR. The value bar, retention bar, candidate evidence and validation in `SKILL.md` apply to every lane; this file adds the order of work. Each step ends on its completion criterion; start the next one only when it is met.

1. **Baseline.** Pin the base SHA; record the subsystem's test and support line counts and every in-scope test file's pass or fail state. Keep baseline failures in their own list: they are often product bugs, not stale tests. Done when every in-scope test file has a recorded baseline result.
2. **Lanes.** Split the surface along production owner boundaries, not file prefixes, until every test file and QA scenario belongs to exactly one lane.
3. **Ledger per lane.** A read-only reviewer per lane reads every assigned test in full, including parameter tables, plus the production owners, callers, history and CI routing. Every test declaration gets one mark and one evidence line; an `it.each` is one declaration unless its rows need different marks.
   - `R` retain: name the contract and the bug it catches.
   - `F` fix: keep the contract, repair the assertion (for example a vacuous negative that passes when only one of several items is missing).
   - `C` consolidate: name the owner that absorbs the assertion first.
   - `D` delete: name the proof that remains, or why no contract exists.
   Done when every declaration in the lane has a mark and an evidence line.
4. **Layer plan.** The ledger is input, not the edit list. A second read-only pass finds the redundant layer: suites that replay one component through a mocked collaborator beside stronger real-boundary suites. Name the keeper suite per contract, preferring the real transport boundary with a fake network; carry the surviving assertions into keepers; list the test-only production seams each lane unlocks. Done when each lane plan names its retired files, its keeper per contract and the seams unlocked.
5. **Cutover.** Edit lane by lane; serialize changes to shared harnesses through one owner. Remove the unlocked seams (injection parameters, getters, reset exports, indirection layers), register moved suites in CI routing, and put durable test-ownership rules in the subsystem's `AGENTS.md`, drawn from mistakes the campaign actually found. Done when every lane plan is applied and each lane's keepers pass.
6. **Preservation review.** Before claiming completion, independent reviewers compare deleted coverage against the keepers, one per boundary group, looking for contracts that lost their only proof and new assertions that cannot fail. For each restored contract, make one deliberate mutation of the production owner, confirm the keeper goes red, then restore the source byte for byte. Done when every reported gap is restored or rejected with source evidence.
7. **Product defects.** A baseline failure that survives into a keeper is a bug. Fix it at its owner in a separate commit and prove it through the real user flow, with a control run that reverts the fix and shows the old behavior. Unrelated discrepancies become follow-ups. Done when each repaired defect has a failing control and a passing candidate on the same harness.
8. **Reconcile.** Merge the base branch rather than rebasing. When the base modified a file the campaign deleted, keep the deletion and port the new contract into the keeper. Rerun the whole subsystem suite, and live proof where it exists, on the merged head. Review tooling may truncate very large diffs; record maintainer decisions in the PR evidence rather than editing gates. Done when the merged head passes. Hand off with the `SKILL.md` report plus baseline and final line counts, lanes, retired layers and keepers, preservation gaps and their mutations, and product defects with control and candidate proof.

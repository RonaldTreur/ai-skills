# Validate retrospective lifecycle evidence

1. Read the target RoundTable checkout's `docs/retrospective-timing-analysis.md` before drafting timing tables; use its exact report fields and current validator contract. Select the configured profile from trusted PR `changed_files` (up to 3: small-fix; up to 20: standard-change; otherwise complex-change), not perceived semantic simplicity. Verify the selection against the current recorder rather than increasing a budget to fit observed time.
2. Bind intake to the earliest local closing source issue, with PR creation only as the documented direct-PR fallback. Include ready, first dispatch, first work, merge, retrospective start and current execution. First check the unique earliest legacy claim: when it is unedited, unrecovered and its `startedAt` is no later than immutable comment creation, bind first dispatch to `startedAt` and first work to creation. If the earliest claim is edited, recovered, ambiguous or invalidly ordered, that legacy path is unavailable and a later claim cannot be promoted to replace it. Dispatch claims are rolling comments, so the fallback uses the trusted `stageFirstStartedAt` map only when every relevant claim carries a complete retained map. Bind first dispatch and first work to the earliest retained `build`, `fix`, `qa` or `review` pickup across the source issue and PR; they share that pickup because GitHub does not expose a separate worker-start boundary. Bind retrospective start by the same immutable legacy-claim rule, or to the retained `retrospective` pickup when that legacy path is unavailable. Refuse retained pickups earlier than readiness or merge and never backfill a legacy claim. A pending retrospective marker is not retrospective start.
3. Build exclusive, non-overlapping segments for active work, queue/scheduler wait, CI, retries/rework and approval/maintainer holds. Include merge-to-retrospective wait explicitly. For complete evidence, require contiguous exact-time coverage of full elapsed; round displayed durations only as the contract permits. For partial evidence, preserve measured intervals, identify unpartitioned time and use `missing`/`unknown` for unavailable boundaries/stages rather than inventing a complete partition. Nested checks are not additive elapsed time. Before finalizing cause names and fingerprints, check stage names against the current validator's category-binding vocabulary: a `retries/rework` row must name retry, rework, repair or fix loop, not merely reconciliation. If validation reports `invalid_stage_category_binding`, correct the descriptive stage name without changing its evidenced category, timestamps or budget; propagate any renamed timing cause into dispositions and recompute affected action fingerprints.
4. Compare both individual segments and cumulative category totals with the configured multiplier and minimum overage. Keep a measured excessive interval excessive even when its cause is unknown. Attribute causes only from evidence; distinguish evidence loss from the cause of historical delay. Use explained holds only with immutable contemporaneous evidence from an authorized holder.
5. For missing historical evidence, use `indeterminate` and terminal disposition `investigation required—evidence missing`. Give every gap and unknown stage its own delay-disposition row. Missing boundaries use exact causes `Lifecycle boundary: <lowercase boundary name>` and must use `Retrospective ledger`; the recorder rejects a per-event action for them. Route an unknown stage to `Investigation required: Action N` only for a specific, reproducible hypothesis; otherwise use `Retrospective ledger`. Include excessive stages and category totals needing investigation in their own rows. Use the ledger for a recurring systemic excessive-delay cause already visible across reports. Never clear a missing-evidence cause with `no action`.
6. Ledger-routed causes do not create per-event action fingerprints or consume action slots. When a concrete action is justified, keep at most five actions by grouping causes only when one bounded investigation covers them. Declare the exact set in `**Timing causes:** ["..."]`, compute its fingerprint with the recorder helper, and give each cause its own disposition row. The durable GitHub result must contain the standalone action marker and one exact `Timing cause: <cause>` line per cause; verify no missing, extra or duplicate causes. Acceptance must require immutable recovered evidence or an explicit irrecoverable result listing sources checked. Queued investigation is event completion, not proof that the investigation or remediation succeeded.
7. Validate the completed report locally with `validateRetrospectiveReport` from `src/retrospective-event.js`, using action routing, event fingerprint, expected profile and trusted boundaries. Apply through the exact guarded event-ledger command with the report file; require `recorded`, then read-only replay returning `already_recorded`. Run `npm run retrospective-ledger:report` in the target RoundTable checkout to aggregate recorded reports. Create the one trusted rolling issue once with `--apply --create`, then refresh only that exact issue with `--apply --issue <number>`. Keep action state/marker checks and apply-time clock validation authoritative.

## Adversarial checks

For report validation, reject baseline escalation, no-action gap clearance, invented or backfilled claim boundaries, per-event actions for lifecycle gaps, omitted merge wait, duplicate stages, hidden cumulative excess and missing cause bindings. Check invalid reports fail for the intended reason, not merely any unrelated error.

When changing the validator itself, also test compensating/split intervals, overlaps, timestamped unknown stages, unsupported prose, unrelated fixes, malformed baselines, fenced or duplicate-field smuggling, and self-declared, edited or post-hoc holds. Bind fixes and holds to the exact event, stage and cause. Replay in-flight legacy records after schema/fingerprint changes; verify an already-recorded event remains a no-op even with malformed current configuration. Accept only when all valid excessive-delay and missing-evidence dispositions remain representable.
